# cvWiz API Reference

Base URL for local development:

```text
http://localhost:8080
```

Use JSON request bodies and set:

```text
Content-Type: application/json
Authorization: Bearer <jwt>
```

`POST /gebruikers/login` is public. In the fully secured configuration, manager endpoints require `ROLE_MANAGER` and consultant self-service endpoints require `ROLE_CONSULTANT`.

Local development note: security is temporarily commented out while client authentication is being wired up. Most endpoints can be called without a bearer token in this mode. The one-time consultant CV endpoint still needs an authenticated consultant because it uses the current username to find the consultant record. See `README.md` for the restore checklist.

## Error Response

Most API errors use this shape:

```json
{
  "status": 400,
  "error": "Bad Request",
  "message": "Request validation failed."
}
```

## Authentication

### Login

`POST /gebruikers/login`

Request:

```json
{
  "username": "piet.puk@codeclan.nl",
  "password": "ManagerPassword123!"
}
```

Response:

```json
{
  "token": "<jwt>"
}
```

User records are created only as part of a manager or consultant record. There is no standalone user-creation endpoint.

## Manager Endpoints

All endpoints below require `ROLE_MANAGER` when full security is restored.

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/beheerders/beheerder?id=<uuid>` | Get a manager |
| `POST` | `/beheerders/nieuw` | Create a manager |
| `POST` | `/beheerders/bewerk` | Update a manager |
| `DELETE` | `/beheerders/verwijder?id=<uuid>` | Delete a manager |
| `POST` | `/beheerders/nieuweMedewerker` | Create a consultant onboarding account |
| `POST` | `/beheerders/updateMedewerker` | Update a consultant |
| `POST` | `/beheerders/nieuweCurriculumVitae?id=<uuid>` | Add a CV to a consultant |
| `DELETE` | `/beheerders/deleteMedewerker?voornaam=<name>&achternaam=<name>` | Delete a consultant |
| `POST` | `/beheerders/nieuweCategory?category=<name>&techniek=<name>` | Add a skill category |
| `POST` | `/beheerders/nieuweTechniek?category=<name>&techniek=<name>` | Add a skill |
| `GET` | `/beheerders/matrix?id=<id>` | Get a skill matrix |
| `GET` | `/beheerders/curriculumVitae?id=<id>` | Get a CV |
| `POST` | `/beheerders/curriculumVitae/update` | Update a CV |
| `POST` | `/beheerders/curriculumVitae/update/originale?voornaam=<name>&achternaam=<name>` | Update a consultant's original CV |
| `GET` | `/beheerders/gebruikers` | List user full names |

The old typo path `/beheerders/nieweCategory` is still accepted as a compatibility alias.

### Create Consultant Onboarding Account

`POST /beheerders/nieuweMedewerker`

Request:

```json
{
  "id": null,
  "voornaam": "Ada",
  "achternaam": "Lovelace",
  "telefoon": "06-12345678",
  "emailAdres": "ada.lovelace@example.com",
  "orgineleCv": null,
  "cvLijst": []
}
```

Response:

```json
{
  "consultant": {
    "id": "<consultant-id>",
    "voornaam": "Ada",
    "achternaam": "Lovelace",
    "telefoon": "06-12345678",
    "emailAdres": "ada.lovelace@example.com",
    "orgineleCv": null,
    "cvLijst": []
  },
  "username": "ada.lovelace@example.com",
  "oneTimePassword": "<generated-password>"
}
```

The generated password is returned once. After the consultant completes the first CV, the same JWT can still be used to submit `/medewerkers/updateMedewerker`. The consultant account is disabled after that own-profile update is saved.

### ID Rules

All entity ids are generated by the API. Clients should not invent ids for new objects.

- For create requests, send `"id": null` or omit the id.
- For a new nested object inside an update request, always send `"id": null`.
- For updating an existing object, send the id that was returned earlier by the API.
- Do not reuse an existing id for a new object. For example, a new `ervaring` item in a CV update must have `"id": null`; otherwise it is treated as an update of that existing experience.

### CV Body Example

```json
{
  "id": null,
  "bestandsNaam": "cv_ada_lovelace",
  "competenties": [
    "Java",
    "Spring Boot",
    "API testing"
  ],
  "languages": {
    "Dutch": "Native",
    "English": "Professional"
  },
  "profiel": "Experienced software consultant.",
  "opleiding": "Computer Science",
  "matrix": null,
  "ervaring": []
}
```

For `POST /beheerders/nieuweCurriculumVitae?id=<uuid>`, the consultant id belongs in the query string. The CV body id should be `null` or omitted for a new CV.

For `POST /beheerders/curriculumVitae/update`, the top-level CV `id` is required and must already exist. New nested objects inside that CV still need `"id": null`.

Nested CV save rules:

- `"matrix": null` creates a new matrix from the base matrix.
- `"matrix": { "id": null, "matrix": { ... } }` creates a new matrix from the submitted scores.
- `"matrix": { "id": 1, "matrix": { ... } }` updates the existing matrix with id `1`.
- Submitted matrices are completed against base matrix `1` before they are saved or updated. Any missing base categories or tools are added with the base/default value, while submitted scores are kept.
- `"languages"` is required for CV save and update requests. It is an object where each key is the language and each value is the niveau.
- Experience entries with `"id": null` are created and receive a generated id.
- Experience entries with an existing `"id"` are updated.
- `"ervaring": []` is accepted.

String values may contain apostrophes, for example `"Candidate's profile"`. Raw control characters are removed before JSON parsing. Malformed JSON still returns the standard invalid body response:

```json
{
  "status": 400,
  "error": "Bad Request",
  "message": "Invalid request body."
}
```

Update CV example with a submitted new matrix and a submitted new experience:

```json
{
  "id": 1,
  "bestandsNaam": "cv_ada_lovelace_updated",
  "competenties": [
    "Java",
    "Spring Boot",
    "API testing"
  ],
  "languages": {
    "Dutch": "Native",
    "English": "Professional",
    "German": "Intermediate"
  },
  "profiel": "Candidate's profile updated.",
  "opleiding": "Computer Science",
  "matrix": {
    "id": null,
    "matrix": {
      "Testing": {
        "Playwright": 4
      }
    }
  },
  "ervaring": [
    {
      "id": null,
      "bedrijf": "New Company",
      "periode": "2026",
      "functie": "Tester",
      "sector": "IT",
      "kennis": "Java",
      "situatie": "New situation",
      "taak": "New task"
    }
  ]
}
```

## Consultant Endpoints

All endpoints below require `ROLE_CONSULTANT` when full security is restored.

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/medewerkers/medewerker?id=<uuid>` | Get own consultant record |
| `POST` | `/medewerkers/updateMedewerker` | Update own consultant record |
| `POST` | `/medewerkers/curriculumVitae/eersteLogin` | Complete one-time CV onboarding |

The one-time CV onboarding endpoint creates the consultant's original CV. The same JWT remains valid for the follow-up own-profile update, and the consultant login is disabled after that update is saved.

## Postman Collection

Import the local Postman collection:

```text
docs/postman/cvWiz.postman_collection.json
```

PowerShell-friendly cURL snippets are also available:

```text
docs/postman/cvWiz.curl.md
```

Recommended order:

1. `Auth / Login as seeded manager`
2. `Manager / Create consultant onboarding user`
3. `Auth / Login as generated consultant`
4. `Consultant / Complete one-time CV`
5. `Consultant / Update own consultant record`

The Postman collection stores JWTs and generated onboarding values as collection variables.
